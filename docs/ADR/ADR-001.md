# ADR-001 — Estratégia de Desenvolvimento (Walking Skeleton)

## Status
Aceito

---

## Contexto
O roadmap original do projeto (definido no README) previa uma sequência linear:
infraestrutura completa (AWS, Databricks) → ingestão → transformação → BI → IA.

Essa abordagem é comum em empresas onde a plataforma de dados já existe e o time
chega depois para construir sobre ela. Em um projeto pessoal solo, no entanto, ela
carrega um risco real: é possível gastar semanas configurando contas, permissões e
serviços sem nunca ter validado se o pipeline funciona ponta a ponta — e sem esse
feedback, o risco de abandono do projeto antes da primeira entrega tangível aumenta.

Além disso, decisões de infraestrutura tomadas sem um caso de uso real rodando
(ex: estrutura de buckets, granularidade de permissões, escolha de camadas)
tendem a ser especulativas e frequentemente precisam ser revisadas assim que o
primeiro dado real passa a fluir pelo sistema.

---

## Decisão
Adotar a estratégia **Walking Skeleton**: construir primeiro um fluxo mínimo,
fino e completo, atravessando todas as camadas da arquitetura antes de
aprofundar ou expandir escopo.
